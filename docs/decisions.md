# Decisions

Short log of calls that aren't obvious from the code. Newest at the bottom.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-12 | Single monorepo: docs, design, content and code together | Solo project; spec, content and code change together. App in `apps/mobile`, backend in `supabase/`. |
| 2026-10-12 | Native Expo app first, not a Telegram Mini App | The research leaned Mini App for Uzbek reach and payments. We picked native for polish, offline logging at 3am, widgets and the global market. A Mini App on the same Supabase backend stays an option. |
| 2026-10-12 | expo-sqlite + Drizzle locally, Supabase on the server | Logging must work instantly and offline, so local SQLite is the source of truth. Drizzle gives typed queries and migrations with no runtime weight. Supabase gives Postgres, auth, RLS per family, storage, Edge Functions and pgvector (for card retrieval) in one cheap place. |
| 2026-10-12 | Rejected for v1: PowerSync/ElectricSQL, WatermelonDB, Firebase | PowerSync/Electric: more moving parts or cost (revisit if sync gets painful). WatermelonDB: older, less typed. Firebase: weaker relational queries, harder data residency. |
| 2026-10-12 | Gemini Flash-class for AI answers | Best Uzbek Latin scores on the UzLiB benchmark at low cost (see `research/market-and-ai.md`). |
| 2026-10-12 | ~~Rive for the mascot~~ (superseded, see the Skia row below) | One file with a state machine whose phase can be driven by data. Needs a dev build. |
| 2026-10-12 | Uzbekistan payments via activation codes sold outside the app | Uzcard/Humo can't pay in the stores, and store rules limit linking to outside payment. Codes keep the app compliant. |
| 2026-10-12 | Red-flag rules and test cases live in `/content/safety` | The device and the Edge Function must run the exact same rules. |
| 2026-10-12 | Routes in `apps/mobile/src/app/` | Expo Router's default when there's a `src/` folder, so all app code sits in one place. |
| 2026-10-12 | M1 log sheet uses expo-router's native `formSheet`, not `@gorhom/bottom-sheet` | Native sheet with no extra deps for M1. So `react-native-reanimated`, `react-native-gesture-handler` and `@gorhom/bottom-sheet` aren't direct deps yet; add them when motion work needs them. |
| 2026-10-12 | Design phase before M2: brainstorm, flows, wireframes, brand, design system, screens | Shokhnur wants the look and flows settled in Figma before more code. M1 stays as a grey skeleton. Plan in `design/plan.md`. |
| 2026-10-12 | Brand colours: A2 "Saffron and indigo" with Source Serif 4 + Onest | Shokhnur's pick from 6 options (`design/03-brand-directions.md`). Indigo ink and a saffron moon echo ikat and suzani without using pattern, and no other baby app owns them. Night becomes deep indigo with warm saffron and cream text instead of amber-on-brown; it stays very dark with no white flashes. |
| ~~2026-10-12~~ | ~~Logo: saffron Moon o mark + Source Serif 4 "oyjon" wordmark. App icon: "Night", a glossy 3D Moon o in an indigo sky, in the style of Dmitri Litvinov's icons~~ | Superseded by "Moon in the word" below. The Night app icon stays. |
| 2026-10-12 | Final logo: "Moon in the word". The moon is the o of the serif "oyjon" wordmark (Source Serif 4, tightened tracking), with no separate mark. App icon stays "Night" | Shokhnur approved it ("okay let's go with it"). Being finalised on the 05 Brand page in Figma. |
| 2026-10-12 | Moon character personality: A "Oyim", a quiet older-sister type who speaks rarely and smiles a lot | Shokhnur's pick from `docs/spec/companion.md`. She'll be drawn in the same glossy 3D style as the app icon. |
| 2026-10-12 | Oyim final look: "Moonstone" with Grok-style pill eyes (Figma node 47:2) | Shokhnur rejected the first glossy emoji-like sketch as childish; the Moonstone variants made on the Mac with the local prototype skills were approved ("way better now"). Animation: Skia + Reanimated (row below). |
| 2026-10-12 | Oyim is animated in code with `@shopify/react-native-skia` + Reanimated, not Rive | Shokhnur's call. Moonstone is built from simple shapes and gradients, so it can be drawn in code with its phase, gaze, blink and mood driven straight from app state. No separate editor file. Skia is a native module, so it still needs the dev build. |
| 2026-10-12 | Brand final: Saffron and indigo (indigo hue 275, saffron oklch 0.83 0.14 84, turquoise second accent), night gradient #262D5C to #0C0F27, "Moon in the word" logo with full guidelines, Night sky app icon in three iOS 18 appearances, Oyim Moonstone in Skia + Reanimated | Shokhnur kept the current hues on the Colour decisions board and approved the logo and icon guideline boards. Summary in `design/07-brand-final.md`. |
| 2026-10-13 | All open v1 flow decisions and keep/drop questions settled as Claude's picks, including keeping the centre + as a small log sheet | Shokhnur said to go on with the next tasks. Each pick is marked "Decided" in `design/08` to `design/13` and on the FigJam flow pages. He can still change any of them. |
| 2026-10-13 | Global-first, native-Uzbek-focused: every Uzbekistan-specific value in the v1 flows comes from her country or language setting, with Uzbekistan as the default | An Uzbek mum gets Uzbek Latin, 103, Tashkent time and Telegram with no setup, and the same app works anywhere. Full list in `design/14-global-ready.md`. Adds one country picker sheet (O1, O6, Settings). |
| 2026-10-13 | Sign-in: Apple (iPhone) or Google (Android) first everywhere. Phone number second in Uzbekistan only, code by Telegram with SMS fallback. Elsewhere an email code under "Other ways". "Later" always stays | Shokhnur locked the picks from the sign-in methods research. One tap and free for most people, while Uzbek mums keep the phone login they trust from Payme, Click and Uzum. |
